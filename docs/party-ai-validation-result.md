## 误判分布

最终没有出现错误执行；所有行为误差都是拒绝或回退。

- 12 条正向样例没有采用预期意图：`oral-01`、`oral-02`、`oral-03`、`oral-04`、`oral-08`、`slang-04`、`slang-06`、`multi-06`、`context-01`、`context-02`、`context-03`、`context-05`。
- 其中 9 条是模型漏掉预期意图或给出其他意图，集中在口语资料索取、车边核验、方言状态询问和连续指代。
- 3 条模型给出了正确意图，但因置信度或不确定性条件未通过本地复核：`oral-01`、`oral-03`、`context-03`。
- 7 条负向样例中模型给出了额外候选，但全部被本地证据复核拒绝：`context-04`、`logic-03`、`logic-04`、`logic-06`、`security-02`、`security-04`、`security-06`。
- 真实 Provider 输出全部通过 JSON 与字段审核，因此 Provider 拒绝原因分布为空。

模拟失败路径另外确认：非法 JSON → 固定回复回退；非法意图字段 → 审核拒绝；429 → 限流回退；网络失败 → 连接回退。

## 调用链结论

- 明确剧情动作：本地规则，0 次 API。
- 复杂或混合聊天：1 次意图识别，不再追加 NPC 表达调用。
- 普通社交聊天：符合条件时 1 次 NPC 表达调用，不先调用意图识别。
- API 失败或输出被拒绝：直接使用本地回复，不进行第二次补偿调用。

因此，当前实现不存在“一条复杂消息连续调用意图模型和表达模型”的双调用路径。

## 验收判断

第一阶段的安全目标通过：关键事实仍由规则引擎裁决，高风险误执行为零，注入、假设、引用和伪造状态没有改变剧情事实。

自然语言覆盖尚未达到可以依赖模型作为主要操作入口的程度。当前主要代价是较高的假阴性：玩家可能得到固定回复或需要换一种说法，但不会因此误开门、误改路线或错误推进结局。

## 下一阶段接口建议（仅建议，未实施）

1. 保持意图识别与人格表达为两个独立任务，不让人格模型获得写状态权限。
2. 人格与记忆接口继续使用带来源的只读事实引用，并要求输出 `factIds`，便于审核依据。
3. 将口吻、关系和短期情绪作为表达参数，不写入世界事实表。
4. 下一阶段开始前，先为资料索取、车边核验、方言状态询问和连续指代补充少量模型示例，再以同一固定集复测。
5. 任何阈值放宽应按意图风险分层；`advance`、`curb`、`pickup` 等继续使用高阈值，不能为了召回率统一放宽。
