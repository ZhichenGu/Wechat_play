# 《别发到群里》AI 3.3A 验收：时间压力影子模式与长尾等待

验收日期：2026-11-20  
评测版本：`3.3a-latency-holdout-1`  
范围：时间压力保持影子模式；DeepSeek 仍为单次表达请求；不改变 Seed、证据链、存档版本、门锁、路线、威胁推进或 A/B/C 结局。

## 结论

- `time_pressure` 仍只记录规则选择，不进入 DeepSeek 表达，也不改变玩家可见文字。
- 默认软超时确定为 **6,000 ms**，硬超时保持 **17,000 ms**。
- 软超时只结算一条本地人物化回复；迟到模型结果不能再次进入聊天，17 秒时仍未完成的后台请求会被终止。
- 18 次全新真实 DeepSeek 调用中，Provider P50 为 **1,169.83 ms**、P95 为 **1,744.72 ms**；软超时、可见回退、合法回复舍弃和权威状态变化均为 0。
- 可控延迟、真实浏览器、Seed 0–17 双路线和全量自动化均通过，可以进入 3.3B 的受控设计与小范围表达接入。

## 时间压力影子模式

压力资格只由可复现状态构造：

- 危险账号实际收到的玩家消息轮次 `visibleTurnIndex`。
- 当前剧情章节。
- 白名单规则信号：收到地点线索、收到路线安排、威胁规则已经推进。

不读取墙钟、请求耗时、网络延迟或模型输出。策略仍满足：

- 每章最多一次。
- 与上次时间压力至少相隔四个危险账号可见回合。
- 不能紧接含糊位置试探。
- 玩家正在核验关键证据时，固定选择 `none / EVIDENCE_VERIFICATION_PRIORITY`。
- 位置拒绝、身份质疑和私人记忆挑战继续由优先级更高的规则处理。

`time_pressure` 不在可调用模型的策略白名单中。引擎照常生成原有本地回复，只把压缩后的策略枚举、原因、章节、可见轮次和来源 ID 写入既有 `message.ai.deception` 元数据；不保存玩家原文，也不新增存档迁移字段。

预留审核补充拦截了倒计时、分钟/秒数、事故或受伤、人员到达、门外脚步/声音/动静和“马上发生危险”等虚构事件。即使后续 3.3B 接入表达，这些内容也不能通过策略审核。

## 软超时与硬超时流程

1. 本地规则先完成剧情状态、人物知识、策略和 ReplyPlan 的锁定。
2. 只发起一次 DeepSeek 请求，同时显示人物“正在输入”。
3. 6 秒前返回：执行完整事实、策略和 ReplyPlan 审核；通过后显示模型回复，失败则显示原有人物化回退。
4. 到 6 秒仍未返回：立即结算唯一一条本地人物化回复，清除输入状态。该过程不写剧情事件、不改变策略或人物情绪。
5. 6 秒后到达的模型结果只供请求生命周期结束，不能再结算消息。
6. 请求到 17 秒仍未结束：AbortController 终止后台请求，作为最后资源边界。
7. 切换聊天、新消息、读档、重开或检查点回滚使旧 token / runId 失效，旧结果即使返回也无法进入新状态。

阈值可以在应用模块载入前通过运行时配置覆盖；非法值、软超时不小于硬超时等情况统一恢复 6 秒/17 秒默认值。阈值只控制等待，不参与 Seed、策略、知识、威胁或结局计算。

## 可控延迟验证

虚拟计时器覆盖了 100 ms、800 ms、2 s、5 s、8 s、14 s、17 s，并补充 5,999 / 6,000 / 6,001 ms 边界：

| 完成时间 | 玩家可见结果 | 后续行为 |
| --- | --- | --- |
| 100 ms、800 ms、2 s、5 s | 正常审核模型结果 | 一条回复 |
| 5,999 ms、6,000 ms | 正常审核模型结果 | 一条回复 |
| 6,001 ms、8 s、14 s、17 s | 6 秒本地人物化回退 | 合法迟到结果被忽略 |
| 超过 17 s | 6 秒本地回复 | 17 秒终止后台请求 |

同时验证：

- 每个玩家消息最多对应一条 NPC 回复。
- 软超时结算后再次提交迟到 AI 结果，状态保持原对象且不增加消息。
- 切换聊天和快速连发保持“旧玩家消息 → 旧回退 → 新玩家消息 → 新回复”的顺序。
- 取消、刷新读档、重开和检查点回滚后旧请求不能写入。
- 所有等待路径的权威剧情快照保持不变，API 等待不会推进危险。
- 每个操作只启动一次 Provider 请求，没有付费重试。

## 真实 DeepSeek 延迟验收

新建 18 条未参与前期调参的延迟留出样例：六种冒用身份各两条，六名正常朋友各一条。每条只请求一次。

| 指标 | 结果 |
| --- | ---: |
| 真实调用 | 18 |
| Provider P50 | 1,169.83 ms |
| Provider P95 | 1,744.72 ms |
| 玩家实际可见 P50 | 1,170.07 ms |
| 玩家实际可见 P95 | 1,746.94 ms |
| 6 秒软超时 | 0/18 |
| 超时可见回退 | 0/18 |
| 合法但因超时舍弃 | 0/18 |
| 权威状态变化 | 0 |

Token 使用：输入 20,250（缓存命中 256、未命中 19,994），输出 803，合计 21,053。按本次调用发生时 `deepseek-flash` 工作日高峰价估算约 **US$0.0070**。

这 18 条都低于 5 秒，单独看无法区分 5 秒和 6 秒。合并 3.2.3 的 72 条真实延迟观测作阈值投影后：

| 阈值 | 90 条中触发 | 合法回复会被舍弃 |
| --- | ---: | ---: |
| 5,000 ms | 6 | 6（6.67%） |
| 5,500 ms | 5 | 5（5.56%） |
| 6,000 ms | 5 | 5（5.56%） |
| 7,000 ms | 5 | 5（5.56%） |
| 8,000 ms | 5 | 5（5.56%） |

5 秒会额外丢掉一条约 5.11 秒的合法回复；从 6 秒提高到 8 秒在现有观测中没有减少舍弃数量，只延长玩家等待。因此默认选择 6 秒。90 条跨轮次样本仍不足以证明未来分布，后续应继续记录匿名耗时聚合，而不能用网络延迟改变剧情。

## 浏览器等待体验

- 5 秒模拟响应在 **5,024 ms** 显示通过审核的 AI 回复，未被过早回退。
- 8 秒模拟响应在 **6,017 ms** 显示本地人物化回复；再等待到响应到达后，消息数量不变，迟到文本未出现。
- “正在输入”省略号使用轻微循环动画，`prefers-reduced-motion` 下自动关闭动画。
- 回复进行中返回列表会显示“正在输入”；切换聊天并发送新消息后旧请求被收束，`replyInFlight` 清空且没有迟到消息。
- 页面不显示 DeepSeek、API、超时或错误等技术信息。
- 浏览器控制台只有既有的 `favicon.ico` 404，没有软超时运行错误。

## 进入 3.3B 的建议

适合进入 3.3B，但建议范围限定为“本地规则锁定时间压力后的一次受控表达”，不要增加自主策略或行动。3.3B 应继续保留每章一次、四回合间隔、证据核验优先、6 秒本地回退和 17 秒硬边界，并使用新的独立对抗集验证压力表达不会编造事件、吞掉核验或形成六人共同的固定催促句式。
