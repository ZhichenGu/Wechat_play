# 生日散场篇 · PT-03 / AI 3.3B.1 封闭真人首玩

本版本只用于一对一或小范围主持的封闭试玩。线上版本运行在独立的 `wechat-play-closed` Worker 和独立 D1 配额数据库中，不连接或覆盖正式实例；游戏进度和研究记录仍只保存在试玩浏览器。入口由访问口令保护，不应公开转发。

## 线上主持人运行

1. 使用交付信息中的“主持人入口”打开页面。第一次打开会建立七天有效的 HttpOnly 访问 Cookie，并立即从地址栏移除访问口令。
2. 打开右上角“会话设置”，在“主持人设置”中粘贴 DeepSeek API Key，点击“启用自然对话”。状态应显示“自然对话已开启”。
3. 点击“进入普通试玩界面”，再把同一个标签页交给试玩者。不要另开标签页：API Key 只保存在当前标签页的浏览器会话中。
4. 普通试玩界面不会显示 API Key、主持人设置、Seed、策略名称或记录导出入口。试玩中不要打开浏览器开发者工具。

API Key 只作为请求头发送给封闭 Worker，再由 Worker 代理到 DeepSeek；它不会写入游戏存档、试玩记录、服务器数据库、仓库或地址栏。关闭该标签页后会话 Key 消失。主持人也可以回到主持人入口手动清除。

若自然对话状态显示为本地回复，不要把该局计入真实 AI 首玩结果；可继续完整游玩并在记录中标记 `local-fallback`，或由主持人重新进入设置检查 Key。

## 本机备用运行

1. 确认项目根目录的 `.dev.vars` 已配置 `NPC_API_KEY`。不要截图、导出或向试玩者展示这个文件。
2. 在项目根目录运行：

   ```bash
   npm run start:playtest
   ```

3. 看到本机预览地址后，使用独立浏览器访客档案打开：

   `http://127.0.0.1:4185/?party=1&playtest=1`

4. 从“会话设置”确认“角色自然对话”已开启；状态应显示“自然对话已开启”。

该地址只监听 `127.0.0.1`，同一局应在运行预览的电脑上完成。首次搭建依赖时才需要运行 `npm ci`。

若真实接口确实不可用，可以运行 `npm run start:playtest:local` 保留完整主线并排查界面，但这局会在记录中标为 `local-fallback`，不能计入真实 AI 首玩结果。不要把固定回复局与真实接口局混在同一组体验结论里。

## 可直接发给试玩者的说明

> 这是一款通过聊天调查异常、协调朋友离开的中文通信恐怖游戏。请像平时用聊天软件一样阅读消息、私聊朋友或在群里发送文字。聊天页右下角的“+”可以打开文件、位置、通话、门锁和可选回复；“发现”页可以查看当前目标、提示、文件和存档。游戏会自动保存，设置里的“存档与重试”可回到已有检查点。卡住时可以先看当前提示，也可以直接在聊天里向人物求助。请按自己的判断游玩，不需要猜设计者想要的固定句子。试玩过程中不要查看源码、浏览器存储或主持人的记录文件。

不要向试玩者提前说明 Seed、危险身份、正确路线、证据顺序、压力策略或 A/B/C 结局条件。

## 记录与导出

试玩结束后，由主持人在同一个标签页重新打开交付信息中的主持人入口，或在普通地址末尾加上 `&research=1`，进入主持人研究入口。线上地址中的访问口令只用于第一次建立 Cookie，不应写入记录或截图。

本机备用入口仍是：`http://127.0.0.1:4185/?party=1&playtest=1&research=1`

然后从「发现 → 存档与重试 → 本地试玩记录」导出 JSON；结局页也会出现同一入口。普通试玩入口仍会静默记录，但不显示记录按钮、Seed 或内部统计。建议在重开、换测试者或关闭访客档案前立即导出。每次重开或从检查点重试会开始一份新记录，读档继续同一局则沿用原记录。

导出内容包括：

- PT-03、AI 3.3B.1、剧情修订、Seed、开始/结束时间和各阶段首次到达时间。
- 首次由玩家明确表达的怀疑、身份核验尝试和核验成立事件。
- 信息泄露类别、补救操作、出口变化、危险推进、结局和规则给出的具体原因。
- 时间压力出现次数，以及玩家收到压力回复后的下一类操作。
- 当前提示、主动求助和建议回复使用次数。
- AI 成功、审核回退、6 秒软超时和本地回退次数；本局使用真实接口还是本地回退模式。

记录不保存 API 密钥，不抄录玩家输入或模型回复原文，也不收集姓名、联系方式等个人信息。消息来源只保留游戏内部 ID 和必要分类。Seed、内部事件与策略统计只存在导出的研究记录中，正常试玩界面不显示答案。

首次怀疑只有在玩家把怀疑说进聊天时才能自动记录；如果玩家只是在心里怀疑，请主持人在访谈中补记时间点和依据。导出文件仍是本机研究材料，不应公开转发。

## 主持人观察清单

| 观察点 | 记录什么 |
| --- | --- |
| 首玩时长 | 从开场到第一次结局的时间；暂停或离开屏幕的时间另记。第一次完成与检查点续测分开。 |
| 首次怀疑 | 什么时候开始怀疑、怀疑谁、刚看到什么；不要在过程中追问，以免提示答案。 |
| 卡点与提示 | 是找不到入口、看不懂线索、不会组织话，还是句子未被正确理解；记下提示前后行为。 |
| 身份核验 | 玩家如何区分账号说法、独立证据和现场确认；是否把说话风格误当成身份证明。 |
| 泄露与补救 | 玩家是否理解文字、位置、引用、截图和路线实际发给谁；泄露后是否发现并采取有效补救。 |
| 时间压力 | 压力回复出现后，玩家下一步是照做、核验、拒绝、沉默还是转移话题；体感是朋友催促还是系统催进度。 |
| 七人会合 | 玩家能否解释谁找到真人、谁在楼外、从哪个出口接走、车辆如何确认人员到齐。 |
| AI 体验 | 是否出现明显回退、长时间“正在输入”、风格突变、答非所问或固定句式暴露危险账号。 |
| 界面稳定性 | 首次进入、聊天切换、自动保存、读档、重开、结局与导出是否正常；注明桌面或手机宽度。 |

中途只在试玩者明确求助时提供界面操作帮助，不提供身份、路线或证据答案。将结果标为“无协助首玩”“协助首玩”或“检查点续测”；开发自测不能记作真人首玩。

## 试玩后访谈提纲

1. 你第一次觉得某条消息或某个账号不对是什么时候？具体依据是什么？
2. 哪一步最不知道该做什么？是入口、线索、自然语言理解，还是不知道该联系谁？
3. 你用什么方法核验身份？哪些证据让你相信，哪些只算对方自己的说法？
4. 你觉得房号、位置、引用、截图和出口信息分别被谁收到了？发生泄露时你是否意识到了？
5. 出现催促或压力感的回复后，你做了什么？它像朋友在说话，还是像游戏在催你？有没有让你觉得必须照做？
6. 不看结局说明，你能否复述七个人如何会合，或在哪一步没能会合？
7. 哪个人最像真实朋友？哪条回复最像模板、最突兀或最不像这个人？
8. “正在输入”的等待是否影响节奏？有没有看到明显的固定回复或迟到、重复、乱序消息？
9. 从开始到第一次结局用了多久？紧张感 1–5 分是多少？最高点和最低点分别在哪里？
10. 如果只改一件事，你最希望改什么？

## 当前已知限制

- 3.3B 主独立留出集严格通过 43/48，可见回退率 10.4%，尚不满足正式部署目标；本轮只适合封闭观察。
- 模型回复具有在线波动，同一局可由 Seed 复现规则状态，但不能保证逐字复现模型措辞。
- 6 秒软超时会舍弃迟到的合法回复并显示人物化本地回退；17 秒仍是请求的最后边界。
- 记录保存在浏览器本地。清理站点数据、关闭未持久化的访客档案或先重开再导出都可能丢失上一局记录。
- 线上访问 Cookie 最长保留七天；API Key 仅保留在设置它的标签页会话中。换设备、换浏览器、另开标签页或关闭后，都需要主持人重新设置 Key。
- `workers.dev` 在部分网络环境可能被限制；当前已从浏览器实测线上入口可打开，但正式邀请前仍应在试玩者实际网络中先做一次可达性检查。
- 本项目是客户端权威剧情系统。普通界面已隐藏 Seed、危险账号和策略名称，但浏览器存储与打包代码不是密码学意义上的保密边界；测试者需同意不检查开发者工具或源码。
- 自动记录能观察玩家实际输入和规则事件，不能推断玩家没有说出口的想法；首次怀疑和主观压力仍需访谈补充。
