# 生日散场篇 · PT-03 真人盲测

在测试电脑运行 `npm start -- 4185`，打开 [生日散场篇记录模式](http://127.0.0.1:4185/?party=1&playtest=1)。本机地址只能在运行预览的电脑访问。第一次搭建可先运行 `npm ci`。用独立浏览器窗口或访客档案开始新局。试玩者只需要知道这是一款用聊天调查和协调离开的游戏。请勿先展示 Seed 对照表、危险身份、结局条件和推荐流程。

记录模式只使用本机浏览器存储，可从「发现 → 存档与重试 → 本地试玩记录」查看摘要并导出 JSON。结局页也有同一入口。每次重开或从检查点重试都开始一份新记录，重试注明为续测。请先导出上一份再重开。读档继续原局保留已有记录。从已有进度首次开启记录时，文件会标明开始记录的位置，不能据此推算首玩时间。

文件包含试玩版标识（PT-03）、Seed、剧情修订、起始时间、首次抵达各阶段时间、打开提示、聊天中主动求助、选用建议回复、出口变化、泄露、危险推进、关闭共享、作废访客码、引开和结局原因。房间线索带有分类、送达消息 ID 和原始消息 ID，供复核来源。所有时间使用 ISO 8601 UTC。记录不抄录聊天原文，也不发送到外部服务。正常入口不显示记录工具。

## 观察清单

| 观察点 | 记录什么 |
| --- | --- |
| 首玩时长 | 从开场出现到第一次结局的时间，另记暂停或离开屏幕多久。把第一次完成与检查点后的续测分开。 |
| 首次怀疑 | 试玩者第一次怀疑哪个账号、在什么阶段、刚看到哪条消息或线索。结束后再问「当时是什么让你觉得不对？」 |
| 卡点与提示 | 卡住时正在找入口、看不懂线索，还是知道要做什么但打出的句子没被理解。记下提示前后做了什么、是否又卡了一次。 |
| 信息边界 | 玩家是否知道房号、截图、位置共享和路线分别发给了谁，能否解释为什么换出口还要重新通知接应者。 |
| 会合与风险 | 玩家能否复述谁找到了真人、谁在楼外、从哪扇门接走。若出现泄露，记录玩家是否看懂接近反馈和补救机会。 |

建议先让一位没看过设计的人独立玩一局，中途只在对方明确请求时帮助。第二位可用另一种结构或同一身份的另一查证顺序。结果分别标记无协助首玩、协助首玩或续测。自动测试和开发自测另计。

## 试玩后直接询问

1. 你第一次觉得某条消息或某个账号不对，是什么时候？哪条信息让你开始怀疑？
2. 哪一步最不知道该做什么？打开提示或求助以后，有没有更清楚？
3. 你觉得哪些信息实际被谁收到了？如果出口换了，为什么两边可能还是会错过？
4. 不看结局页，你能用自己的话说说七个人最后是如何会合的，或在哪一步没能会合吗？
5. 从开始到第一次结局用了多久？紧张感打 1–5 分的话是多少？最紧张的是哪一刻？
