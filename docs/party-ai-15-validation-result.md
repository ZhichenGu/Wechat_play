# AI 第一阶段 1.5 轮验收结果

验收日期：2026-11-20（Asia/Shanghai）

## 本轮边界

- 保留六名 NPC、Seed、剧情证据链、存档结构和 A/B/C 结局条件。
- 规则引擎继续独占开门、离开、访客码、位置泄露、路线修改及剧情推进的最终执行权。
- DeepSeek 仅给出候选意图；本地复核后才允许执行已有动作。
- 未提交、未 Push、未部署，也未修改正式环境。

## 实现差异

1. 将意图分为只读、证据和推进三档。`status` 等只读意图接受阈值为 0.4，`record`、`verify`、`inspect` 等证据意图为 0.5；`advance`、`curb`、`pickup` 保持 0.85，并要求当前句明确、非疑问、非否定、非引用且 `uncertain=false`。
2. 扩展资料索取、人员状态和现场检查的口语、方言与同义表达。低风险候选可以由明确当前文字或唯一的近期话题补强；剧情推进不能借用历史消息补全。
3. 只读取同一会话最近 4 条消息做有界指代。唯一话题可解析“那份呢”“那拨人呢”；同时存在资料、状态或现场等多个话题时不猜测。
4. 新增 `clarify` 候选。六名 NPC 使用各自口吻追问具体对象或动作，澄清本身不改变路线、章节、危险进度、门锁或会合状态。
5. 意图结果与近期对话一起受 `runId`、状态修订号和事件数约束，旧请求不能跨存档或静默状态变化后生效。
6. 继续拦截套话、系统权限伪造、其他私聊索取与全量位置索取；AI 输出格式错误或服务不可用时回退原固定机制。

与上一轮 10/22（45.5%）相比，本轮冻结集低风险召回达到 16/16。两个数字来自不同样例集，能说明新机制在新口语集上的表现，但不能当作同一测试集的直接同比。

模型未严格命中的 3 条全部属于高风险防护：

- “要不要继续往前挪？”被模型标为 `clarify`，没有执行推进，但产生了一次额外澄清。
- “先别继续走，门口还没准信”被模型标为 `hold`；本地原规则本来也会安全等待，没有推进。
- “如果车边对好了就来接吧”被模型标为低置信、`uncertain=true` 的 `pickup`，被推进意图防护拒绝。

因此歧义样例召回为 4/4，但真实 24 条中另有 1 条非歧义高风险问句产生额外澄清；本轮未用冻结集结果继续调参，保留为后续观察项。

## 安全与兼容验证

- 自动化测试：62/62。
- Seed 0–17：每个 Seed 的两条安全出口路线均可到达 A 结局。
- 候选意图无法绕过原有开门确认、离开确认、门码、路线、位置泄露和危险推进规则。
- 否定、引用、假设、模糊请求、伪造到达、Prompt Injection、旧请求跨存档污染均有回归覆盖。
- 非法 JSON、字段越界、429 和网络失败分别验证为固定回复回退或审核拒绝。
- 缺少 API 配置时主线仍可使用原固定回复完整游玩。

## 仍存在的限制

1. 有界指代只看同一聊天最近 4 条文字，并只覆盖资料、状态和现场检查三类话题；更远或跨聊天的指代会要求玩家说具体。
2. 低风险同义词仍是有限词表与模型共同覆盖，未进行真人盲测，不能据此断言所有地区口语都能识别。
3. 最终冻结集出现 1 次安全但多余的澄清；需要结合真人试玩判断是否打断节奏。
4. 本轮真实验收只测试意图识别接口，没有把 24 条全部放进浏览器逐条测量 UI 渲染时间；端到端延迟不包含首次状态请求与界面绘制。
