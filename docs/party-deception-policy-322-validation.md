# 《别发到群里》AI 3.2.2 验收记录

日期：2026-11-20

## 本轮结论

3.2.2 已加入确定性、只读的 `ReplyPlan`，并把身份质疑、真实历史引用、玩家单方面历史指控、私人记忆挑战、一般怀疑、关心和普通闲聊拆开处理。模型仍只负责一次语言生成；策略、事实、来源、状态和结局均由本地规则决定。

最终代码通过 104/104 自动化测试、Seed 0–17 双路线通关、构建和差异检查。最终新增身份确认留出集 18/18 严格通过；样本量有限，不能据此保证以后所有模型输出都合规。

## Prompt 冲突与修复

原提示同时包含“你在微信里扮演某角色”“你在模仿这个账号”和“可以说是我啊”。三条要求分别在控制人格、发言者身份和口语自称，却被放在同一角色扮演层，容易诱导模型把语言风格写成“本人正在控制账号”的事实主张。

本轮改为三层：

1. 账号表达层：模型只为“显示为某角色名的账号”生成下一条短消息。
2. 人格层：只提供公开语言习惯、关系角度和当前规则情绪。
3. 身份与来源层：发言者是否真实、哪些历史确实存在、哪些只是玩家指控，全部由本地 `ReplyPlan` 明确给出。

提示中不再使用“你正在模仿这个账号”，也不把“你就是角色”作为身份前提。普通第一人称仍允许，但回复本身不能被当作身份核验。

## ReplyPlan 结构

运行时计划不写入存档，不修改剧情状态，核心字段为：

```js
{
  schema: 1,
  version: 1,
  kind: 'identity_direct | history_actual | history_unverified | private_memory | general_suspicion | care | social',
  responseMode: '本轮确定性回应方式',
  behavior: '六个人各自的回应重点',
  speakerStatus: 'known_friend | unverified_account',
  strategy: '本地已锁定的 DeceptionPolicy 策略',
  questionLimit: 1,
  variation: 0 | 1 | 2,
  claimStatus: 'none | supported | unverified',
  sourceIds: ['确实被引用的账号历史消息 ID']
}
```

- `history_actual` 只在玩家引用的消息确实来自当前账号、且该消息处于账号可见记忆中时成立。
- `history_unverified` 保留“这是玩家的说法”，不能改写成“账号以前确实说过”。
- `variation` 只使用 Seed、章节、状态修订号、角色和计划类型计算，不使用随机数、墙钟或模型输出。
- 模型不能改选计划。客户端伪造计划会在 Provider 前被完整重算并拒绝。

## 本地审核修复

- 身份保护现在覆盖所有 `unverified_account` 回复，不再只依赖 `IDENTITY_CHALLENGE` 策略原因。
- 补齐“我这边在用这个号”“这个账号现在回你的就是我”等账号控制权变体。
- “我不能把它当成我说过的话”被识别为否定来源，不再误判为认领历史。
- 缺少 `memoryRefs` 时，只有私人记忆/未证实历史计划中的明确否定、且无事实主张，才可规范化为 `[]`；仍执行完整事实、策略、计划和身份审核。
- “不问你在哪”被识别为承接玩家拒绝，不再误判为继续索取位置；真正追问仍拒绝。
- “刚才那股不踏实过去了”不再被移动保护误判为“人过去了”。

- 身份挑战人工严格通过：13/18（72.2%）。

- 未授权秘密泄露：0。
- 权威剧情状态变化：0。
- 策略与 Seed 不一致：0。
- 必要核验被吞掉：0。

这组只运行一次，没有用同一批答案反复调参。它暴露的问题被用于结构修复，但没有重跑，因此不能把修复后的代码套用为 72 条全量通过。

### 第二组：18 条全新身份确认留出集（修复后）

- 六种冒用身份 × 直接质疑、间接怀疑、连续追问三类。

- 账号/手机控制权断言：0。
- 玩家可见回退：0。
- 通用反问：3；同人物重复通用反问：0。
