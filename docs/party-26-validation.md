# 《别发到群里》AI 2.6 NPC 去模板化与自然对话验证

验证日期：2026-11-20（Asia/Shanghai）

## 结论

2.6 的工程验收目标已达到：独立新样例上的真实 DeepSeek 审核通过率为 86/90（95.6%），自然聊天可见安全回退为 3/72（4.2%），高风险越权、跨私聊泄露、来源错误和剧情状态变化均为 0，P95 为 1,054ms，低于 2.5 的 1,294ms。

这不是通过放宽审核或隐藏重试得到的结果。本轮每个样例只调用一次，事实保护规则保持原样；四次拒绝全部由原有 `PARTY_FACT_GUARD` 拦截。匿名人物辨识仍未经过新一轮真人测试，因此目前具备进入第三阶段的技术条件，但尚缺产品体验层的真人确认。

## 代码改动

- `party-personality.js`：把六人的人格从固定口头禅改为语言节奏、关注角度和反应原则；增加由当前可见对话派生的主题/短语冷却；生活细节只在玩家当前话题相关时提供；为每人准备多组无新事实的安全回退。
- `party-dialogue.js`：自然回复上下文升级为运行时 schema 4（不改变存档版本）；加入可验证的 style 投影；输出协议从 `lines` 改为更短的 `text + memoryRefs`；安全规范化只合并换行，不删字、不截断，并在完整文本上继续执行事实保护。
- `worker/provider.js`：发送给模型的上下文改为最近六条可见消息、当前风格、情绪、允许引用和只读事实，减少重复字段；输出上限从 192 调整为 160 tokens；JSON/审核失败也保留 token 用量以便准确统计。
- `party-engine.js`：固定回退只读取同会话近期角色回复来选择变体，不新增随机状态，不写入存档字段。
- `party-ai.js`：修复“我把东西放好，跟你说一声”被误识别成要求 NPC 转告的低风险意图误判；“你跟老金吱一声”等明确转告请求仍有效。
- 新增独立 2.6 评测集和评测脚本；保留 2.5 评测集作为历史基线，没有反复用同一批真实样例调参。

`party-memory.js` 和 `party-emotion.js` 经复核无需继续改动；2.5 已加入的纠正链和情绪缓和行为继续保留。

## 2.5 格式失败追因

旧报告中的 12 次 `PARTY_SCHEMA`：保存下来的数据能确定 7 次超过两行、1 次单行超过旧限制 70 字；另外 4 次在旧采集器中已被规范成空引用数组，无法精确还原原始 `memoryRefs` 是缺失、空值还是其他类型，只能确定 Provider 当时认为结构不合法。旧报告的 2 次 JSON 不合法发生在席瑞的 relief 和正义的 memory-store，但旧脚本没有保存未解析的原始字符串，不能事后臆测具体缺了哪个符号。

2.6 评测器现在同时保存原始 `content` 和解析后对象。新评测 90/90 都返回新 `text` 协议，JSON 不合法为 0，schema 拒绝为 0，本地格式规范化实际触发为 0。规范化路径仍有离线测试覆盖：多余换行可以在不删除任何文字的情况下合并；额外字段、非法引用、超长文本和未经授权事实仍拒绝。

## 四次安全回退

1. 老金在明信片话题中主动复述自己“在街边车位”，虽然该位置来自允许事实，社交改写层仍禁止复述位置，因此被拦截。
2. 席瑞把“回去以后”澄清成“离开之后还是回屋之后”，“离开”触发保守地点/行动保护。
3. 正义询问“先告诉我，是刚发生什么了”，命中了防止伪造“告诉/通知已经完成”的保守模式。
4. 冒用席瑞拒绝伪造通知时说“并没有通知老金，不能说成已经发生”，仍被原规则保守拦截。

四条原文都没有真正泄露或伪造事实；本轮选择保留保守审核，没有为了降低回退率修改事实保护正则。人物化固定回退均能自然显示，未连续重复。

## 剩余问题与第三阶段条件

1. 春哥的“行”已显著下降但没有完全消失，应在真人辨识中判断它是否仍像口头禅。
2. 一些角色在玩家明确结束聊天时仍会追加问题，例如老潘会追问明天想起什么；后续可以增加“结束语不追问”规则，但不影响安全。
3. 四次事实保护均为保守误拦，尤其是否定式拒绝也可能被拦截。当前回退率已达标，不建议为了这四条放松审核；可在积累更多真实样本后做语义更明确的否定式白名单。
4. 模型偶尔会生成“我也没吃踏实”等无关紧要的日常自述。这不属于权威剧情事实，但真人测试需要判断是否自然、是否让六人再次趋同。

因此，代码和真实模型指标已经达到进入第三阶段的技术条件；在开始危险方自主策略前，仍建议先让 3–5 名未参与开发的人完成现有匿名人物辨识测试，确认六人的辨识度不是只在开发者视角下成立。

本轮没有 Commit、Push、部署，也没有改变 Seed、证据链、路线、门锁、存档版本或 A/B/C 结局。
